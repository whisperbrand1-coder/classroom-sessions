PART 1 · THE RECIPE 📜

What is an Algorithm?

A precise sequence of instructions a robot follows to complete a task — giving correct and predictable results.

Three building blocks 🧱

Every robot algorithm you will ever write uses these three.

1️⃣

Sequence

Commands run in the correct order — like a recipe. Change the order, change the result.

🔀

Selection

Making decisions: “if the sensor detects something, then turn.”

🔁

Iteration

Repeating with loops — checking a sensor again and again.

SORT Which building block?

THE FLOW 🔄

How an algorithm flows

📡 Sensors give the input · logic processes it · actions are executed · and a result is produced. Then it loops and does it all again — that's Sense → Think → Act.

How to design one

🧩

1 · Decompose

3 · Pseudocode

Write the steps in plain English before touching any blocks.

📝 Pseudocode = a human-readable description of your algorithm, with no real code syntax. It organises your thinking first — then you translate it into blocks, and keep your comments matching the pseudocode.

IT NEVER WORKS FIRST TIME 🐛

Testing & Debugging

⏱️

Test early & often

Run it while you build — don't wait until the end.

🔎

Identify the error

Observe what goes wrong and where.

🔧

Fix one at a time

Small fixes, step by step.

📓

Use evidence

Note what works — don't repeat mistakes.

🌱 The debugging mindset: errors are not failures — they are learning. Test small parts first, write down what you tried, and ask for help: fresh eyes find bugs faster.

HOW MANY EYES? 📡

Sensor-based algorithms

The robot decides using sensor data, not fixed movements.

Single sensorMultiple sensors
UsesOne sensor (e.g. Distance)Two or more (e.g. Distance + DownEye)
Good newsEasier to design & understandBetter awareness, handles complex situations
Trade-offLimited informationNeeds more logic & careful planning
Use it when…The task is simpleThe environment is complex or changing
🤔 Choosing: it depends on the challenge. Simple task → one sensor is fine. Changing playground → you will need more than one.
THE BIG IDEA 🏰

Fixed Path vs Smart Robot

Both robots run at once. Press Shuffle to change the layout — then watch what happens. 👀

🤖

Fixed path

“drive, turn, drive…” — it assumes the world never changes. One reshuffle and it crashes. 💥

🦾

Sensor-based

“if object ahead → turn, else → forward.” It reacts to what it detects, so any layout works. ✅

🧠 Ask the class: “Why did the red robot work the first time but fail after the shuffle?” → because it was following a plan, not reality. That is exactly why Dynamic Castle Crasher needs sensors.

CHALLENGE · 25 MIN

Dynamic Castle Crasher 🏰

Knock all the pieces off the playground as fast as possible — but the layout changes on every reset. Your algorithm must work every time.

🖥️ In VEXcode VR: click Select Playground → choose Dynamic Castle Crasher.

The code, block by block

when started
forever
   repeat until ⟨DownEye detects red?⟩
        if ⟨FrontDistance found an object?⟩ then
             drive forward
        else
             turn right
   drive reverse for 300 mm
   turn right for 90 degrees
  • forever — keeps the robot working continuously.
  • repeat until DownEye detects red? — runs until it finds the red target on the ground.
  • if … else — object ahead? drive into it. Nothing there? turn and search.
  • reverse + turn — backs off and repositions after reaching the goal.
